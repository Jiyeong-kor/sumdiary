# SumDiary Data Map

## 1. 문서 정보

- 제품명: SumDiary
- 문서 목적: SumDiary가 처리하는 데이터의 생성 위치, 저장 위치, 전송 여부, 보유 기간, 삭제 방법, 스토어 신고 기준을 정의한다.
- 작성일: 2026-06-04
- 상태: 초안
- 1차 출시 국가: 대한민국
- 1차 출시 플랫폼: Android, iOS

## 2. 제품 결정 기준

- SumDiary 자체 계정은 제공하지 않는다.
- SumDiary 자체 백업 서버는 운영하지 않는다.
- 일기 요약은 온디바이스 AI로 처리한다.
- AI 요약을 위해 일기 원문을 외부 AI 서버로 전송하지 않는다.
- 클라우드 백업은 사용자가 명시적으로 켠 경우에만 수행한다.
- 클라우드 백업은 사용자가 직접 연결한 외부 클라우드 계정에 암호화된 백업 파일로 저장한다.
- 외부 클라우드에는 평문 일기 원문, 평문 요약문, 평문 감정 태그를 저장하지 않는다.

## 3. 데이터 분류 원칙

- 일기 원문은 민감정보가 포함될 가능성이 높은 데이터로 분류한다.
- 요약문과 감정 태그도 원문에서 파생된 민감 가능 데이터로 분류한다.
- OAuth token은 계정 접근 권한을 부여할 수 있으므로 보안 민감 데이터로 분류한다.
- 암호화 키, 백업 비밀번호, 복구 문구는 백업 복구 가능성을 좌우하는 최고 민감 데이터로 분류한다.
- 로그와 crash report에는 일기 원문, 요약문, 감정 태그, OAuth token, 암호화 키가 포함되면 안 된다.

## 4. 데이터 흐름 요약

```text
User Input
  -> Local App State
  -> Local Database
  -> On-device AI Summary
  -> Local Database
  -> Optional Encrypted Backup File
  -> User-owned External Cloud
```

금지 흐름:

```text
Diary Plaintext -> External AI Server
Diary Plaintext -> Analytics
Diary Plaintext -> Crash Report
Diary Plaintext -> Plain Cloud File
OAuth Token -> Backup File
Encryption Key -> Backup File
```

## 6. 저장 위치별 정리

### 6.1 로컬 DB

포함:

- 일기 원문
- 일기 메타데이터
- 요약문
- 감정 태그
- 사용자 설정 일부

요구사항:

- OS 수준 앱 sandbox 안에 저장한다.
- 앱 수준 암호화 적용 가능성을 검토한다.
- 전체 데이터 삭제 시 함께 삭제한다.
- debug export 기능을 제공하지 않는다.

### 6.2 로컬 설정 저장소

포함:

- 백업 on/off
- 연결 provider
- 마지막 백업 시간
- provider file id
- provider 계정 표시명 일부

요구사항:

- 민감 데이터는 저장하지 않는다.
- OAuth token은 일반 설정 저장소에 저장하지 않는다.

### 6.3 OS 보안 저장소

Android:

- Keystore
- EncryptedSharedPreferences 또는 동등한 보안 저장소

iOS:

- Keychain

포함:

- OAuth token
- 선택적 복구 보조 키

제외:

- 일기 원문
- 요약문
- 감정 태그
- 백업 파일 payload

### 6.4 외부 클라우드

포함:

- 암호화된 백업 파일

제외:

- 평문 일기 원문
- 평문 요약문
- 평문 감정 태그
- OAuth token
- 암호화 키
- 백업 비밀번호

요구사항:

- 사용자가 백업을 켠 경우에만 업로드한다.
- 사용자가 삭제를 요청하면 SumDiary 백업 파일 삭제를 시도한다.
- 외부 클라우드 계정 자체 삭제는 provider 정책에 따른다.

## 7. 제3자 및 외부 제공자

### Google Drive

- 사용 목적: 사용자가 선택한 암호화 백업 파일 저장/복구
- 접근 범위: 최소 scope, 앱 전용 폴더 또는 앱 생성 파일 범위 우선
- 전송 데이터: 암호화된 백업 파일, 파일 metadata
- 평문 원문 전송: 금지
- 삭제: 앱에서 SumDiary 백업 파일 삭제 시도

### Dropbox

- 상태: 후속 후보
- 사용 목적: Google Drive와 동일
- 접근 범위: 앱 전용 폴더 우선
- 평문 원문 전송: 금지

### iCloud Drive

- 상태: 후속 후보 또는 iOS 보조 옵션
- 사용 목적: iOS 사용자 백업
- 제약: Android와 직접 동기화 어려움

### Analytics

- 1차 출시에서는 도입 최소화를 권장한다.
- 도입 시 원문, 요약문, 감정 태그, provider 계정 정보, OAuth token 전송 금지.

### Crash Reporting

- 도입 시 crash payload 필터링을 적용한다.
- 원문, 요약문, 감정 태그, OAuth token, 암호화 키 전송 금지.

## 8. 동의 및 고지

### 필수 고지

- 일기에는 민감정보가 포함될 수 있다.
- 요약은 온디바이스 AI로 생성된다.
- AI 요약을 위해 일기 원문을 외부 AI 서버로 보내지 않는다.
- 클라우드 백업은 사용자가 켠 경우에만 동작한다.
- 백업 파일은 외부 클라우드 업로드 전 암호화된다.
- 백업 비밀번호 또는 복구 문구를 잃어버리면 복구할 수 없다.
- Face ID, Touch ID, Android 생체 인증은 같은 기기에서 백업 키 접근을 편하게 승인하기 위한 기능이며, 새 기기 복구 수단을 대체하지 않는다.
- SumDiary는 사용자의 얼굴, 지문 등 생체정보 원본을 수집하거나 저장하지 않는다.
- 외부 클라우드 제공자는 암호화된 파일과 파일 metadata를 처리할 수 있다.
- 외부 클라우드 계정 자체 삭제는 해당 제공자에서 해야 한다.

### 별도 동의 후보

- 민감정보 가능 데이터 처리 동의
- 클라우드 백업 사용 동의
- 외부 클라우드 OAuth 연결 동의
- 선택적 crash/analytics 수집 동의

## 10. 스토어 신고 기준 초안

### Google Play Data safety

검토 필요:

- 앱이 로컬에서 개인 및 민감 사용자 데이터를 처리한다.
- 사용자가 선택하면 암호화된 백업 파일을 외부 클라우드에 업로드한다.
- Google Drive API를 사용할 경우 Google 사용자 데이터 scope를 요청한다.
- crash/analytics SDK를 도입하면 수집 항목이 추가될 수 있다.

주의:

- 사용자가 외부 클라우드에 직접 업로드하는 구조라도 앱이 데이터를 생성, 암호화, 업로드하므로 신고 문구를 보수적으로 작성한다.
- 평문 원문을 수집/공유하지 않는다는 표현은 네트워크 캡처와 로그 테스트로 검증한다.

### Apple App Privacy

검토 필요:

- 사용자 콘텐츠: 일기 원문, 요약문, 감정 태그
- 식별자: provider 계정 표시명 또는 provider user id를 저장하는 경우
- 진단: crash report 도입 시
- 사용 데이터: analytics 도입 시

주의:

- 1차 출시에서는 Google Drive SDK/API 사용 여부를 App Privacy와 개인정보처리방침에 반영한다.
- Dropbox 또는 iCloud Drive를 후속 지원할 경우 App Privacy와 개인정보처리방침을 다시 업데이트한다.

## 11. 출시 전 검증

- 백업 파일을 외부에서 열어도 평문이 보이지 않는다.
- 백업 파일 metadata에 일기 내용이 없다.
- 네트워크 캡처에 평문 일기 원문이 없다.
- 로그에 일기 원문, 요약문, 감정 태그가 없다.
- OAuth token이 일반 설정 저장소나 백업 파일에 없다.
- 외부 클라우드 연결 해제 시 로컬 token이 삭제된다.
- 백업 파일 삭제 요청 후 provider에서 파일이 삭제된다.
- 백업 비밀번호 분실 시 복구 불가 고지가 표시된다.
- 생체 인증을 다시 등록하거나 새 기기에서 복구할 때 백업 비밀번호 또는 복구 문구가 필요하다는 고지가 표시된다.
- 개인정보처리방침이 실제 데이터 흐름과 일치한다.
- Google Play Data safety와 Apple App Privacy 답변이 실제 구현과 일치한다.

## 12. 오픈 이슈

- 백업 비밀번호를 기본 복구 수단으로 하고, 생체 인증은 같은 기기에서 키 접근을 승인하는 편의 기능으로 제공한다.
- 복구 문구를 1차 출시에서 고급 옵션으로 제공할지 후속 기능으로 둘지 결정한다.
- 로컬 DB 앱 수준 암호화를 1차 출시 범위에 포함할지 결정한다.
- crash reporting과 analytics를 1차 출시에서 사용할지 결정한다.
- 민감정보 별도 동의 문구를 법무 검토한다.
