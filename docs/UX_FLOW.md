# SumDiary UX Flow

## 1. 문서 정보

- 제품명: SumDiary
- 문서 목적: UI 구현 전에 첫 실행, 일기, 요약, 백업, 복구, 생체 인증, 햅틱 흐름과 예외 상태를 정의한다.
- 작성일: 2026-06-04
- 상태: 초안
- 관련 문서: `docs/PRD.md`, `docs/APP_IA.md`, `docs/BACKUP_ARCHITECTURE.md`, `docs/DATA_MAP.md`
- 관련 이슈: Refs #9

## 2. UX 원칙

- 일기 작성은 가장 빠른 흐름으로 유지한다.
- 개인정보와 백업 고지는 기능 소개용 온보딩과 분리한다.
- 사용자가 이해하지 못한 상태에서 클라우드 백업, AI 처리, 생체 인증을 켜지 않는다.
- 민감한 선택은 한 화면에 한 결정만 둔다.
- 실패 상태는 사용자가 다음 행동을 알 수 있게 복구 액션을 제공한다.
- Android와 iOS는 동일한 의사결정 구조를 유지하되, UI 표현은 각 플랫폼 관습을 따른다.

## 3. 첫 실행 흐름

### 3.1 목표

첫 실행에서는 사용자가 앱의 핵심 가치를 이해하고, 법적으로 필요한 고지와 선택을 마친 뒤, 일기 탭까지 안전하게 진입하게 한다.

### 3.2 전체 흐름

```text
앱 실행
  -> 앱 가이드 표시 여부 확인
  -> 앱 가이드
  -> 개인정보/민감정보 가능성 고지
  -> 온디바이스 AI 처리 설명
  -> 기본 설정 완료
  -> 일기 탭
```

### 3.3 앱 가이드

앱 가이드는 기능 소개 화면이다. 법적 동의 화면을 대체하지 않는다.

권장 화면:

1. 짧게 남기는 하루 기록
2. 기기 안에서 만드는 요약
3. 사용자가 켜는 Google Drive 암호화 백업
4. 생체 인증과 햅틱으로 더 안전하고 자연스럽게 쓰기

주 액션:

- 마지막 화면: `시작하기`
- 보조 액션: `건너뛰기`

건너뛰기 정책:

- 이미 사용해 본 사용자를 위해 작게 제공한다.
- 기능 소개만 건너뛴다.
- 개인정보/민감정보 가능성 고지, 필수 동의, 백업 opt-in 고지는 건너뛸 수 없다.
- 설정에서 앱 가이드를 다시 볼 수 있다.

### 3.4 필수 고지와 선택

앱 가이드 이후 다음 내용을 별도 화면으로 제공한다.

- 일기에는 민감정보가 포함될 수 있음
- 일기 원문은 로컬 저장소에 저장됨
- 요약은 기본적으로 온디바이스 처리임
- 클라우드 백업은 사용자가 켠 경우에만 동작함
- 외부 클라우드 연결 시 Google Drive 계정과 권한 요청이 필요함

필수 고지 화면 액션:

- 각 필수 고지 항목 확인
- 모든 필수 고지를 확인한 뒤 `확인하고 계속`

Android 첫 실행 화면은 기능 소개 뒤 별도 필수 고지 화면을 표시하며, 민감정보 가능성, 온디바이스 AI 처리 조건, Google Drive 백업 opt-in 고지를 각각 확인해야 계속 진행할 수 있다.

금지:

- 필수 고지를 앱 가이드 안의 작은 문구로만 처리하지 않는다.
- 백업을 기본 켜짐으로 만들지 않는다.
- 온디바이스 AI 설명을 외부 전송 없음의 일반 보증처럼 과장하지 않는다.

## 4. 일기 흐름

### 4.1 오늘 일기 목록

진입:

```text
앱 실행 또는 일기 탭 선택
  -> 오늘 날짜 계산
  -> 오늘 일기 observe
  -> 목록 표시
```

상태:

- loading: 저장소 연결 또는 초기 조회 중
- empty: 오늘 작성한 일기 없음
- content: 작성 시간순 일기 목록
- error: 로컬 저장소 조회 실패

빈 상태 문구 방향:

- 사용자를 재촉하지 않는다.
- 오늘 기록을 시작할 수 있는 작성 액션을 함께 제공한다.

### 4.2 일기 작성

흐름:

```text
일기 탭
  -> 작성 버튼
  -> 입력 화면
  -> 저장
  -> 입력 검증
  -> 로컬 저장
  -> 목록 갱신
  -> 저장 성공 피드백
```

입력 검증:

- 공백만 있는 일기는 저장하지 않는다.
- 너무 긴 입력은 저장 정책 확정 전까지 제한 문구를 준비한다.
- 저장 중에는 중복 저장을 막는다.

저장 성공:

- 다이얼로그 또는 작성 화면을 닫는다.
- 목록 상단 또는 시간순 위치에 새 일기를 반영한다.
- 햅틱이 켜져 있으면 짧은 성공 피드백을 준다.

저장 실패:

- 입력 내용은 유지한다.
- `다시 시도` 액션을 제공한다.
- 로그에 원문을 남기지 않는다.

### 4.3 일기 수정

흐름:

```text
일기 목록
  -> 일기 선택
  -> 상세 또는 수정 화면
  -> 내용 수정
  -> 저장
  -> 목록 갱신
```

정책:

- 수정 중 뒤로 가기 시 변경사항 폐기 확인을 제공한다.
- 수정 실패 시 기존 저장본은 유지한다.
- 수정 로그에 원문 diff를 남기지 않는다.

### 4.4 일기 삭제

흐름:

```text
일기 상세
  -> 삭제
  -> 삭제 확인
  -> 로컬 삭제
  -> 목록 갱신
```

삭제 확인:

- 삭제 대상이 로컬 일기임을 명확히 표시한다.
- 백업이 켜져 있으면 다음 백업에서 삭제 상태가 반영될 수 있음을 안내한다.

햅틱:

- 삭제 확정 시 경고 또는 강한 피드백을 1회 제공한다.

## 5. 요약 흐름

### 5.1 요약 탭 진입

흐름:

```text
요약 탭 선택
  -> 오늘 날짜 기준 기간 계산
  -> 기존 요약 조회
  -> 요약 상태 표시
```

상태:

- no entries: 해당 기간 기록 없음
- not generated: 기록은 있지만 요약 없음
- loading: 요약 생성 중
- content: 요약문과 감정 태그 표시
- unsupported: 온디바이스 AI 미지원
- failed: 요약 생성 실패

### 5.2 오늘 요약

흐름:

```text
오늘 요약 선택
  -> 오늘 일기 조회
  -> 온디바이스 AI 지원 확인
  -> 요약 생성
  -> 결과 저장
  -> 결과 표시
```

정책:

- 기록이 없으면 요약 생성을 실행하지 않는다.
- 온디바이스 AI 미지원 시 클라우드 AI fallback을 자동 실행하지 않는다.
- 요약 결과는 사실 확정이 아니라 회고 보조로 표현한다.

### 5.3 이번 주 요약

흐름:

```text
이번 주 요약 선택
  -> 주간 기간 계산
  -> 기간 내 일기 조회
  -> 온디바이스 AI 지원 확인
  -> 요약 생성
  -> 결과 저장
  -> 결과 표시
```

주간 기간:

- 1차 기준은 월요일 시작이다.
- locale 기준 변경은 후속 결정 항목으로 둔다.

### 5.4 요약 실패와 미지원

미지원 상태 문구 방향:

- 이 기기에서는 아직 온디바이스 요약을 사용할 수 없음을 설명한다.
- 일기 작성과 로컬 저장은 계속 사용할 수 있음을 명확히 한다.
- 클라우드 AI 전환을 자동으로 제안하지 않는다.

실패 상태 액션:

- `다시 시도`
- `나중에 하기`
- `지원 정보 보기`

## 6. Google Drive 백업 흐름

### 6.1 백업 켜기

흐름:

```text
설정
  -> 백업 설정
  -> 백업 설명
  -> Google Drive 연결
  -> 백업 비밀번호 생성
  -> 비밀번호 확인
  -> 생체 인증 사용 선택
  -> 첫 백업 실행
  -> 백업 완료
```

백업 설명에 포함할 내용:

- 백업은 사용자가 켠 경우에만 실행된다.
- 백업 파일은 앱에서 암호화한 뒤 Google Drive에 저장된다.
- Google Drive는 암호화된 백업 파일을 보관한다.
- 백업 비밀번호를 잃으면 새 기기에서 복구할 수 없다.
- Face ID/Touch ID/Android 생체 인증은 복구 비밀번호를 대체하지 않는다.

### 6.2 Google Drive 연결

흐름:

```text
Google Drive 연결 선택
  -> OAuth 권한 설명
  -> Google 계정 선택
  -> 권한 승인
  -> 연결 완료
```

권한 설명:

- 필요한 최소 권한만 요청한다.
- 앱 백업 파일 생성/조회/삭제 목적을 설명한다.
- 연결 해제 방법을 안내한다.

### 6.3 수동 백업

흐름:

```text
백업 설정
  -> 지금 백업
  -> 로컬 데이터 직렬화
  -> 암호화
  -> Google Drive 업로드
  -> 완료 상태 표시
```

상태:

- preparing
- encrypting
- uploading
- success
- failed

실패 예시:

- 네트워크 없음
- Google 인증 만료
- Drive 용량 부족
- 권한 취소
- 암호화 실패

실패 액션:

- `다시 시도`
- `Google Drive 다시 연결`
- `백업 끄기`

### 6.4 자동 백업

정책:

- 사용자가 백업을 켠 뒤에만 동작한다.
- 일기 저장 직후 즉시 업로드보다 짧은 지연 또는 예약 백업을 우선한다.
- 배터리, 네트워크, 중복 업로드를 고려한다.
- 자동 백업 실패는 조용히 숨기지 않고 설정 화면에서 상태를 확인할 수 있게 한다.

## 7. 복구 흐름

### 7.1 새 기기 복구

흐름:

```text
첫 실행 또는 설정
  -> 복구 시작
  -> Google Drive 연결
  -> 백업 파일 찾기
  -> 백업 비밀번호 입력
  -> 복호화
  -> 복구 방식 선택
  -> 복구 실행
  -> 완료
```

복구 방식:

- 병합: 기존 로컬 데이터와 백업 데이터를 함께 유지한다.
- 교체: 로컬 데이터를 삭제하고 백업 데이터로 대체한다.

교체 선택 시:

- 강한 확인 화면을 제공한다.
- 로컬 데이터 삭제 영향을 명확히 설명한다.

### 7.2 복구 실패

실패 예시:

- 백업 파일 없음
- 비밀번호 불일치
- 백업 파일 손상
- 지원하지 않는 백업 버전
- Google Drive 권한 만료

복구 실패 UX:

- 실패 원인을 사용자가 이해할 수 있게 표시한다.
- 비밀번호 불일치와 파일 손상을 구분한다.
- 비밀번호를 서버에서 복구할 수 없음을 명확히 한다.
- 원본 로컬 데이터는 복구 성공 전까지 보존한다.

## 8. 생체 인증 흐름

### 8.1 앱 잠금

흐름:

```text
설정
  -> 보안
  -> 생체 인증 사용
  -> OS 생체 인증 확인
  -> 앱 잠금 켜짐
```

정책:

- OS가 제공하는 Face ID, Touch ID, Android biometrics를 사용한다.
- 생체 인증 실패 시 OS 기본 fallback 정책을 따른다.
- 생체 인증은 로컬 접근 편의 기능이다.
- 백업 비밀번호 또는 복구 수단을 대체하지 않는다.

### 8.2 백업 키 접근 승인

흐름:

```text
백업 설정
  -> 백업 관련 민감 작업
  -> 생체 인증 또는 기기 인증
  -> 작업 진행
```

적용 대상:

- 백업 비밀번호 변경
- 백업 끄기
- 백업 파일 삭제
- 복구 방식 교체 선택

## 9. 데이터 삭제 흐름

### 9.1 로컬 데이터 삭제

흐름:

```text
설정
  -> 개인정보 및 데이터
  -> 로컬 데이터 삭제
  -> 삭제 범위 확인
  -> 삭제 실행
  -> 완료
```

삭제 대상:

- 일기 원문
- 요약문
- 감정 태그
- 로컬 캐시
- 로컬 색인

### 9.2 클라우드 백업 파일 삭제

흐름:

```text
설정
  -> 백업 설정
  -> Google Drive 백업 파일 삭제
  -> Google Drive 연결 상태 확인
  -> 삭제 확인
  -> 삭제 실행
  -> 완료
```

정책:

- 로컬 데이터 삭제와 클라우드 백업 삭제는 별도 선택으로 제공한다.
- 사용자가 외부 클라우드 제공자 UI에서도 파일을 확인/삭제할 수 있음을 안내한다.
- Google 계정 자체 삭제는 Google에서 수행해야 함을 설명한다.

## 10. 햅틱 흐름

### 10.1 적용 지점

햅틱은 의미 있는 결과에만 사용한다.

- 일기 저장 성공: light success
- 일기 삭제 확정: warning
- 백업 완료: success
- 백업 실패: error
- 복구 완료: success
- 복구 실패: error

### 10.2 비적용 지점

- 탭 전환
- 일반 스크롤
- 일반 버튼 탭
- 텍스트 입력
- 반복적으로 발생하는 loading 상태

### 10.3 설정과 접근성

- 기본값은 켜짐으로 둔다.
- 설정에서 끌 수 있다.
- OS의 햅틱/접근성 설정을 존중한다.
- 생체 인증 성공/실패는 OS 기본 피드백을 우선한다.

- delete failed

### 요약

- loading
- generated

- generation failed

- password setup
- ready

- provider connect required

- biometrics disabled
- biometrics enabled
- authentication failed
- fallback required

## 12. 법무/스토어 심사 메모

- 앱 가이드의 `건너뛰기`는 기능 소개에만 적용한다.
- 개인정보/민감정보 가능성 고지와 백업 opt-in은 별도 흐름으로 둔다.
- 온디바이스 AI 설명은 실제 구현과 네트워크 동작이 일치해야 한다.
- Google Drive 권한 요청 전 목적, 범위, 삭제 방법을 설명한다.
- 백업 비밀번호 분실 시 복구 불가 문구를 명확히 표시한다.
- 감정 태그는 정신건강 진단처럼 표현하지 않는다.
- 스토어 스크린샷에는 실제 사용자 일기 원문을 노출하지 않는다.
